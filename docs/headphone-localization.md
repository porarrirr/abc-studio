# イヤホン定位：論文と実装判断

2026-10-21。狙いは、指揮者の前に並ぶ楽器の方向と奥行きを、聴く人が比較して調整できること。左右の分離、前後の正確さ、頭外定位、距離、音色は別の評価項目として扱う。

## 実装

- `HeadphoneRendering.swift` と `OrchestraSpatializer.swift`：各被験者の前方水平面25方向、左右各200タップ、44.1kHzの実測FIRを全長畳み込み。実測に含まれるITD・ILD・耳介の周波数特性を使い、従来の人工パン・遅延を二重には加えない。左右の解剖学的非対称性も残す。
- 舞台座標は指揮者から見て右が正。SOFAは左が正なので抽出時に符号を反転。位相を揃えないFIR同士の補間はコムフィルタを作り得るため、最も近い実測角度を選ぶ。角度の量子化は残る。
- 各候補の全水平面・両耳の平均インパルスエネルギーを基準に、候補ごとに単一の係数でスケーリング。左右・角度別の正規化はせず、相対的な手掛かりを保持。これは周波数特性の補正や知覚的な等ラウドネス保証ではない。
- 奥行きによる直接音の減衰と穏やかな高域減衰、左右で異なる17〜81msの反射、共通ホールを併用する。反射と減衰の係数は実装上の音作りであり、論文から一意に導出された最適値や実測BRIRではない。
- 5か所（左前・正面・右前・手前・舞台奥）で同一の決定論的なノイズを再生。無音の合間を挟み、全候補で刺激・順序・基準レベルを揃える。音楽のミックスによるマスキングを減らして比較できる。
- 方向のわかりやすさ、正面・頭外に感じる度合い、音色の自然さを別々に記録。自動で最高得点を採用しない。広がり・部屋の設定を変えた場合は比較条件が変わるため評価を消し、再試聴する。
- 候補・広がり・部屋の設定をUserDefaultsに保存し、再起動後・通常再生・WAV書き出しに同じ値を使う。候補の比較評価は試聴画面内のみで保持する。

## 検証の範囲

畳み込みの方向と末尾、実測データの同梱、左右の取り違え、設定別キャッシュ、両耳の異なる反射、有限値、保存と復元、既存の再生操作、WAV、UI操作を自動検証する。

耳での精度や頭外感は自動テストでは保証できない。実装により改善するという仮説は、本人のイヤホンでの比較で確認する必要がある。候補3件は比較用の小さな集合であり、全CIPIC被験者から最適な部分集合を選定した結果ではない。真後ろ・上下のレンダリング、個人測定HRTF、イヤホンの個別補正、頭部追従は今回の範囲外。舞台奥も「後頭部」ではなく、正面の舞台内で遠い位置を意味する。

## データの再現と権利

`Sources/Audio/HRTF/HeadphoneHRTF.json` に元データURL・SHA-256・スケーリング係数を保存。`scripts/prepare_headphone_hrtf.py` をnumpy/h5py入りの一時venvで実行すると再生成できる。アプリ自体の実行時依存・ダウンロードは不要。
