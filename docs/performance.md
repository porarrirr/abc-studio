# テンポ変換の高速化

2026-10-17。再生スケジューリング、バッファ先読み、WAV書き出しが共有する
`PlaybackSequence.seconds(forBeat:)` と、再生クロックの秒→拍変換を改善した。
従来は問い合わせごとにテンポ表の先頭から積分していた。
テンポ境界の累積秒を初期化時に保存し、二分探索で区間を選ぶことで、
問い合わせの計算量を O(テンポ数) から O(log テンポ数) に変更した。
追加メモリはテンポ境界ごとに Double 1個。テンポ表の変更時には索引も更新する。

## 再現方法

```sh
# 変更前: この最適化前のコミットのソースを指定する
git show fb00d5a:Sources/Audio/ABCSequencer.swift > /tmp/ABCSequencer-before.swift
sh scripts/benchmark_tempo.sh /tmp/ABCSequencer-before.swift

# 変更後
sh scripts/benchmark_tempo.sh
```

Apple M2 / macOS 27.0.1 / Xcode 27.0、Swift の `-O -whole-module-optimization`
で実行。アプリの Release と同じ最適化方式を使う。
ABCを実際にパース・シーケンス化した後、全音の開始時刻と終了時刻を100周計算する。
1回ウォームアップし、7回の中央値を採用する。入力生成・パース・シーケンス化は計時外。
テンポ変更のある16・256・1024小節と、テンポ一定の1024小節を測定する。
各小節は4音。出力のチェックサムでも計算結果を比較できる。

## 測定結果

以下は全音の時間変換100周分の中央値。改善率は `(変更前−変更後)/変更前`。

- テンポ変更あり・16小節: 0.079ms → 0.088ms（0.009ms増加）。小さい入力では探索の効果は出ない。
- テンポ変更あり・256小節: 21.906ms → 3.624ms（83.5%短縮）。
- テンポ変更あり・1024小節: 419.184ms → 20.455ms（95.1%短縮）。
- テンポ一定・1024小節: 0.623ms → 0.409ms（34.3%短縮）。

全ケースで変更前後のチェックサムは一致した。短い処理の絶対値は実行時の環境に左右される。

この測定は時間変換のCPUコストであり、起動時間、譜面描画、音声デコード、
WAV書き出し全体、端末上のフレームレートが同じ割合で改善することを示すものではない。
テンポ変更の多い長い曲ほど効果が大きく、テンポ一定の曲では従来どおり直接換算する。

## 正しさの検証

単体テストは変更前の線形積分と比較し、空・一定・多数のテンポ変更・同一拍の
テンポ変更・境界の前後・曲外への外挿・秒→拍の逆変換を確認する。
テンポ表の要素変更・追加・置換、および値型コピー後の独立性も検証する。

iOS 27.0 / iPhone 18 Pro Simulatorで単体テスト57件が成功（最終調整後に再実行）。
UIテスト3件も成功し、譜面表示・パート音量・再生停止・スクロール追従を確認した。
